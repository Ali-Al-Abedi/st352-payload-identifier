### `0xF9` — Quad-link 1.5G class (Table 4-16 / §2.3.4) — **was P0 × 2; fixed**

| Bits | Spec field | Spec values | Code mapping (audited) | Verdict |
|------|------------|-------------|-----------------------|---------|
| b7:b6 | Channel assignment | `0h`-`3h` = Ch1-Ch4 | **Was using `(b4 >> 5) & 0x7` (3-bit field shared with `0xF4`)**. Now uses `(b4 >> 6) & 0x3` (2-bit) per §2.3.4. | 🛠 Fixed |

## Findings

| # | Severity | Description | Fix |
|---|----------|-------------|-----|
| **1** | **P0** | `0xF9` was using the same byte-4 decoder as `0xF4` (`bt2077_3_byte4_octa_or_quad`), which reads `(b4 >> 5) & 0x7` as a 3-bit channel field. Per BT.2077-3 §2.3.4 / Table 4-16, `0xF9` channel is **2-bit** (`b7:b6`, Ch1-Ch4) and `b5` is **Reserved=0**. A real `0xF9` VPID with `b5=1` would be misinterpreted: e.g. `F9 CA 20 29` (intended Ch1 b5=1) would have decoded as Ch2 with no warning. | Split into two byte-4 plug-ins: `bt2077_3_byte4_quad` for `0xF9` (b7:b6 ch + b5 Reserved) and `bt2077_3_byte4_octa` for `0xF4` (b7:b5 ch). Round-trip vectors added for Ch1-Ch4 of `0xF9`. |
| **2** | **P0** | `0xF9` byte 4 b3 was being decoded as "Reserved (0) / 3840×2160 (1)" with a warning when b3=0 — this is the **`0xF4` rule, misapplied to `0xF9`**. Per Table 4-16 row "Bit 3", `0xF9` defines b3=0 as **1920×1080** and b3=1 as **3840×2160**, both valid. The tool was emitting a false-positive "Reserved" warning on every HD-source quad-link signal. | Same split fix above resolves this — `bt2077_3_byte4_quad` correctly labels both b3 values without warning. Round-trip vector `F9 CA 20 41` (Ch2 1920×1080) added to lock the behaviour. |
| 3 | P3 | BT.2077-3 §2.3.2 spec text says "Bits b4 shall be used to indicate Transfer Characteristic" with only 0h/1h defined, while Table 4-16 column shows the full 4-value SDR/HLG/PQ/Unspec set (b5:b4). This is a documented spec text typo (consistent across §2.3, §2.4, §2.5, §2.6, §2.7, §2.8). The decoder follows the **table** (the field's primary normative form). | None — table-form interpretation is unambiguous in practice and matches every other ST 2081-x family. |
| 4 | P3 | BT.2077-3 §2.3.4 spec text describes bit-depth value `3h` as "10 bits per sample with full range coding", while Table 4-16 caption labels `3h` as "12-bit full range" (matching the SMPTE-wide convention). The decoder follows the table. | None — typo in spec text. |
| 5 | P2 | Allowed-rate / sampling-Reserved enforcement deferred (global findings #3, #4). | Tracked. |
