## Byte 4 — link / signal / depth (both modes)

| Bits | Spec field | Spec values | Code mapping | Verdict |
|------|------------|-------------|-------------|---------|
| b7:b5 | Link assignment | `0h`=6G-SDI Link 1, `1h`=6G-SDI Link 2; **other values Reserved** | Decoder warns on link ≥ 2 via factory's `linkValid` check (`links=2`). | ✅ |
| b4    | Y'CbCr / ICTCP | `0`=Y'CbCr, `1`=ICTCP | Matches. | ✅ |
| b3    | Reserved (=0) | "Bit b3 shall be Reserved and set to 0" | Decoder warns on `b3=1`. | ✅ |
| b2    | Audio copy / Reserved | "For DS 1 & 2 = Reserved 0; for DS 3-8 = audio copy" | Decoder labels b2 as a free audio-copy bit without DS context (P1; tracked in `0xC0-C1-st2081-10.md` Finding #2). | ⚠️ |
| b1:b0 | Bit depth | **All four values valid** for both modes: `0h`=10-bit FR, `1h`=10-bit, `2h`=12-bit, `3h`=12-bit FR | Layout has `bitDepth12: true` → 12-bit accepted. | ✅ |

> **Important note on Mode 2 (HFR).** Unlike ST 2081-10 Mode 3 (0xC1 HFR
> **single-link**) which restricts bit depth to `0h`/`1h`, ST 2081-11
> Mode 2 (`0xF3`, 1080 HFR **dual-link**) explicitly permits 12-bit and
> 12-bit Full Range. This is because dual-link doubles the bandwidth.
> The `bitDepth12: true` setting on `0xF3` is therefore *correct* and
> must NOT be changed to `'rate-dependent'`.

## Findings

| # | Severity | Description | Fix |
|---|----------|-------------|-----|
| 1 | P1 | Same DS-conditional `b2` ambiguity as ST 2081-10 §4.3.4 / §5.3.4. The spec defines b2 as Reserved=0 for DS 1 & 2 and audio-copy for DS 3-8; the tool labels it unconditionally as audio-copy. | Tracked in `0xC0-C1-st2081-10.md` Finding #2. No change here — the same factory handles all four families. |
| 2 | P2 | Allowed-rate subset (Table 4 ∩ Table 1 / Table 6) not enforced. | Tracked in `0xC0-C1-st2081-10.md` Finding #3. |
| 3 | P2 | Reserved sampling-structure values (Table 5 `7h`, `Bh`, `Ch`, `Dh`, `Fh`) are surfaced as "Reserved" string but no top-of-page warning. | Tracked in `0xC0-C1-st2081-10.md` Finding #4. |
