# Byte 1 = `0xD2` / `0xD3` — SMPTE ST 2082-12:2019

**Spec source.** SMPTE ST 2082-12:2019 — *Carriage of 4320-line and 2160-line Source image formats and ancillary data on a Quad-link 12 Gb/s SDI*

**Scope.**

| Byte 1 | Mode | Image | Section | Table |
|--------|------|-------|---------|-------|
| `0xD2` | Mode 1 | 4320-line (8K) on quad-link 12G-SDI | §4.6 | Table 3 |
| `0xD3` | Mode 2 | 2160-line (4K HFR) on quad-link 12G-SDI | §5.9 | Table 16 |

**PDF.** `docs/smpte/st2082-12-2019.pdf`
**Code under audit.** `vpid.html` — `VPID_LAYOUTS[0xD2]` and `VPID_LAYOUTS[0xD3]` (custom layouts; not the `make6Gor24GLayout` factory, since they have a unique 2-bit link assignment + ICtCp signal-type bit that does not match the 6G/24G factory shape).
**Status.** ✅ **Pass** — three **P1** missing-warnings found and **fixed**, plus one **P1** Mode-1-only sub-image-sampling restriction enforced.
**Auditor.** AI agent, glass-to-glass spec audit, 2026-05-08.
**Round-trip:** smoke-passed; new warnings probed end-to-end (see probe transcript below).

## Findings

| # | ID | Severity | Description | Fix |
|---|----|----------|-------------|-----|
| 1 | D2-prog-transport | **P1** | Byte 2 b7 must be 1 (progressive transport) per §4.6.2 / §5.9.2 — decoder labelled b7=0 as "Interlaced (invalid)" in the field row but did not raise a `warnings` entry. Audit code may suppress the field-text variant when rendering a clean summary. | **Fixed** — added explicit warning on b7≠1 in both 0xD2 and 0xD3 decoders. |
| 2 | D2-prog-picture  | **P1** | Same as #1 for byte 2 b6 (progressive picture). | **Fixed** — added explicit warning on b6≠1. |
| 3 | D2-mode1-hSamp   | **P1** | ST 2082-12 Mode 1 (D2h) Table 3 only lists "1920 (0)" for byte 3 b6 — the 2048 option is exclusive to Mode 2 (Table 16). The decoder previously accepted b6=1 for D2h and labelled the resolution as 8192×4320, which is not a defined Mode 1 image format. | **Fixed** — added warning for `D2h` when b6=1, citing Table 3 vs Table 16. |
| 4 | D2-link-reserved | **P1** | The Mode 1 (D2h) decoder did not warn on byte 4 b7:b5 ∈ {4h-7h}. The Mode 2 (D3h) decoder already warned. Both must reject reserved link-assignment values per §4.6.4 / §5.9.4. | **Fixed** — added the same `link >= 4` warning to D2h. |
| 5 | D2-D3-b3-reserved | **P1** | Byte 4 b3 is Reserved (=0) per §4.6.4 / §5.9.4 in both modes; neither decoder warned on b3=1. | **Fixed** — added explicit warning on b3=1 in both decoders. |
| 6 | D2-D3-b2-DS-context | (informational P3) | b2 (audio copy status) is reserved=0 for data streams 1-8 and meaningful for data streams 9-32. The tool lacks per-stream context, so it labels the field "Audio copy (DS 9-32)" without a warning — same limitation as the ST 2081-x family. | None — global limitation, documented in the rollup. |

No P0 bugs uncovered.
