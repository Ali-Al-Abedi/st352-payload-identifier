## Findings

| # | Severity | Description | Fix |
|---|----------|-------------|-----|
| **1** | **P0** | `0xC5` was registered with `bitDepth12: true`, accepting 12-bit codes (`2h`/`3h`) on **all** rates. Per ST 2081-12 §5.8 Table 9, Mode 2 (low rate) does allow 12-bit; per §6.9 Table 17, Mode 3 (HFR) restricts bit depth to `0h`/`1h` (other values **Reserved**). The tool would have accepted a 12-bit signal at 100Hz/120Hz on a quad-link 6G payload without warning, which is a spec violation. | Changed `0xC5` from `bitDepth12: true` to `'rate-dependent'` — same mechanism as the `0xC1` fix. 12-bit warned only on HFR rate codes (`1h`, `Ch`-`Fh`). 0xC4 unchanged (correctly 10-bit only). |
| 2 | P1 | DS-conditional `b2` interpretation — same as ST 2081-10/-11 finding. | Tracked globally. |
| 3 | P2 | Allowed-rate subset (Table 4 ∩ Table 1 / 6 / 10) not enforced. | Tracked globally. |
| 4 | P2 | Reserved sampling-structure values surface as text "Reserved" without a top-of-page warning. | Tracked globally. |
