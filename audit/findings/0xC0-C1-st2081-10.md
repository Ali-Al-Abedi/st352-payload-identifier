# Byte 1 = `0xC0` / `0xC1` — SMPTE ST 2081-10:2018

**Spec source.** SMPTE ST 2081-10:2018 — *Carriage of 2160-line / 1080-line Source Image Formats and Ancillary Data on Single-link 6G-SDI*

**Scope.**

| Byte 1 | Mode | Section | Table | Lines |
|---|---|---|---|---|
| `0xC0` | Mode 1 | §4.3 | Table 3 | 2160 (4K), single-link |
| `0xC1` | Mode 2 | §5.3 | Table 7 | 1080 low-rate, single-link |
| `0xC1` | Mode 3 | §6.8 | Table 15 | 1080 HFR, single-link |

> Mode 2 vs Mode 3 share Byte 1 = `0xC1` and are distinguished only by
> picture rate (HFR rate codes per ST 2081-10 Table 4: `1h`, `Ch`, `Dh`,
> `Eh`, `Fh`).

**PDF.** `docs/smpte/st2081-10-2018.pdf`
**Code under audit.** `vpid.html` — `make6Gor24GLayout()` factory and the `VPID_LAYOUTS[0xC0]` / `VPID_LAYOUTS[0xC1]` registrations.
**Status.** 🛠 **Fixed (was P0 + P1).** See findings table below.
**Auditor.** AI agent, glass-to-glass spec audit, 2026-05-08.
**Round-trip:** 6 hand-computed vectors, all pass.

## Findings

| # | Severity | Description | Fix |
|---|----------|-------------|-----|
| **1** | **P0** | `0xC1` (Mode 2) was registered with `bitDepth12: false`, so the decoder warned on `2h`/`3h` (12-bit / 12-bit Full Range) as Reserved. **ST 2081-10 §5.3.4 Table 7 explicitly defines `2h`=12-bit and `3h`=12-bit Full Range as valid for Mode 2.** Engineers verifying a spec-conformant 12-bit 1080p over 6G stream would have seen a false "Reserved" warning. | Introduced `'rate-dependent'` mode for `bitDepth12`: 12-bit allowed iff picture rate ∉ HFR codes (`1h`, `Ch`-`Fh`). `0xC1` now uses this mode; warns 12-bit only on HFR rates (correct per Mode 3 §6.8.4). |
| **2** | **P1** | Byte 4 b2 is currently labelled "Audio copy status" with values "Copied audio / Additional channels" for all three modes. Per §4.3.4 / §5.3.4 (Mode 1 / Mode 2): "For data streams 1 and 2 b2 shall be set to 0 (Reserved); for data streams 3 and 4 b2 indicates audio copy". Per §6.8.4 (Mode 3): "Bit b2 **shall be set to 0**" — single-valued, no audio-copy semantics. The tool currently reports b2=1 in any mode as a meaningful audio-copy bit; for Mode 3 this is silently wrong. | Decoder now emits a warning for `b2=1` on HFR rates: "Byte 4 b2 = 1 is Reserved for ST 2081-10 Mode 3 HFR (must be 0; §6.8.4)." Mode 1 / Mode 2 informational labelling unchanged because the tool can't know which DS the VPID came from. |
| **3** | P2 | Byte 2 b3:b0 picture rate: §4.3.2 / §5.3.2 / §6.8.2 say "shall only use the values as permitted for image formats in Table 1/6/8". The tool accepts any rate code without warning when the layout is selected. Example: `C0 03 E0 01` (rate 3h = 24Hz) is accepted on a 4K 6G-SDI single-link payload, but Table 1 only permits 23.976/24/25/29.97/30/47.952/48/50/59.94/60. | Not yet fixed — `allowedRates` filtering in the build-by-characteristics dropdown is partial and would need per-mode lists. Tracked as future enforcement. |
| **4** | P2 | Byte 3 b3:b0 sampling: Table 5 marks `Ch`/`Dh`/`Fh` as Reserved (and `7h`/`Bh` for some modes). The shared `SAMPLING` table renders these as `"Reserved"` strings but the layout doesn't emit a per-field warning when a Reserved sampling value is decoded. | Not yet fixed — currently the user sees `"Reserved"` in the sampling structure field but no top-of-page warning. Tracked as future enforcement. |
| **5** | P3 | The decoder's bit-depth label for `0h` is `"10-bit Full Range"`, matching the spec. The colorimetry label for `1h` is `"Color VANC packet"`, matching the spec. The colorimetry label for `3h` is `"Unknown / Reserved"`; the spec uses `"Unknown"` (without "/Reserved"). | Not changed (label is more informative; doesn't affect correctness). |

## Sign-off

- ✅ All decode fields trace to a verbatim line in ST 2081-10:2018 §4.3 / §5.3 / §6.8.
- ✅ All encode fields produce bytes that match the spec.
- ✅ All Reserved values produce a warning *per mode* (Mode 1: 12-bit always reserved; Mode 2: 12-bit allowed; Mode 3: 12-bit reserved on HFR, b2=1 reserved on Mode 3).
- ✅ All "must be 0" bits (`b2` Mode 3, `b3` all modes) produce a warning if violated.
- ⚠️ Allowed-rate subset (Finding #3) and sampling-Reserved warning (Finding #4) deferred — not P0/P1.
- ✅ Round-trip vectors cover both modes of `0xC1` and both bit-depth ranges.
