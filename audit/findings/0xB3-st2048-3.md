## Findings

| # | ID | Severity | Description | Fix |
|---|----|----------|-------------|-----|
| 1 | B3-scan-field | **P2** | The user-facing `characteristics.scan` field was set from byte 2 b7 (transport) — but ST 2048-3 §7.1 mandates b6 = 1 (progressive picture). For PsF carriage (b7=0, b6=1), the previous decoder labelled the scan "Interlaced", misleading users into thinking the picture content was interlaced. | **Fixed** — `scan` is now derived from `pic` (b6): "Progressive" when transport is also progressive, "Progressive (PsF)" when transport is interlaced (PsF carriage of progressive picture), "Interlaced (invalid)" if b6=0 (which already raises a warning). |
| 2 | B3-allowed-rates | (informational P3) | Field `allowedRates: [0x2, 0x3, 0x5, 0x6, 0x7, 0x9, 0xA, 0xB, 0xC, 0xD, 0xE, 0xF]` is defined but not enforced in the decoder. The spec describes "23.98P-60P" image formats. Strictly informative — the spec doesn't list "reserved" picture-rate codes for 4096×2160. | None — informative. |
| 3 | B3-table1-format-list | (informational P3) | The decoder allowedRates includes high frame rates (96/100/120) that aren't listed in the source format Table 1 ("23.98P-60P"). | None — see #2. |

No P0 / P1 bugs uncovered.
